技能 1 · beautiful-shadows

独立可构建 CSS 特效
🌫️
beautiful-shadows
应用精确的 Tailwind 阴影工具，实现精致的中性分层提升效果。用于紧凑卡片、控件、面板、popover、hero 媒体、特性标注、modal 类容器。
✅ 通过
真实场景
拾穗果园品牌页需要一个"产品卡片"模块：展示苹果品种图片、名称、甜度 rating、单价。卡片需要精致的阴影层次感，在桌面和移动端都看起来高档。
应用 beautiful-shadows sm/md/lg 后的实现
/* beautiful-shadows skill — Three-layer neutral elevation */

beautiful-shadows 实战验证 — 拾穗果园产品卡片

技能 2 · animation-on-scroll

独立可构建 视口动画
👁️
animation-on-scroll
使用 IntersectionObserver 触发视口进入动画，提供 Tailwind-friendly 的动画类和关键帧。用于 scroll-reveal、animate-on-scroll、或视口元素序列动画。
✅ 通过
真实场景
拾穗果园品牌页的"工艺日志"模块有 6 个日志条目，需要每个条目在进入视口时依次淡入（上移 + 模糊消除），营造手工感、叙事感。
应用 animation-on-scroll 后的实现
/* 1) Keyframes — 插入 <head> */
@keyframes animationIn {
  0%   { opacity: 0; transform: translateY(30px); filter: blur(8px); }
  100% { opacity: 1; transform: translateY(0); filter: blur(0px); }
}

/* 2) IntersectionObserver snippet — 插入 <head> */
<script>
(function () {
  const style = document.createElement('style');
  style.textContent = '.animate-on-scroll{animation-play-state:paused!important}'
    +'.animate-on-scroll.animate{animation-play-state:running!important}';
  document.head.appendChild(style);
  const once = true;
  if (!window.__inViewIO) {
    window.__inViewIO = new IntersectionObserver((entries) => {
      entries.forEach((entry) => {
        if (entry.isIntersecting) {
          entry.target.classList.add('animate');
          if (once) window.__inViewIO.unobserve(entry.target);
        }
      });
    }, { threshold: 0.2, rootMargin: '0px 0px -10% 0px' });
  }
  window.initInViewAnimations = function (selector = '.animate-on-scroll') {
    document.querySelectorAll(selector).forEach((el) => { window.__inViewIO.observe(el); });
  };
  document.addEventListener('DOMContentLoaded', () => initInViewAnimations());
})();
</script>

/* 3) 元素使用 — stagger 延迟实现序列动画 */
<div class="animate-on-scroll [animation:animationIn_0.8s_ease-out_0.1s_both]">条目 1</div>
<div class="animate-on-scroll [animation:animationIn_0.8s_ease-out_0.25s_both]">条目 2</div>
<div class="animate-on-scroll [animation:animationIn_0.8s_ease-out_0.4s_both]">条目 3</div>
/* 通过 delay 参数控制 stagger，不是 JS 循环 */
animation-on-scroll 实战验证 — 滚动查看条目依次淡入
✅
零依赖
纯原生 IntersectionObserver + CSS keyframes，不需 GSAP/Lottie/Framer Motion
✅
Tailwind 兼容
动画时长/延迟通过 Tailwind arbitrary values `[animation:...]` 注入，无缝配合
✅
Stagger 简单
每个元素的 delay 值直接写在行内 style，SKILL 没有提到但可行
💡
SKILL 的盲点
SKILL 没写 stagger 方案，实际需要 CSS animation-delay 或 JS 循环注入，目前用行内 style 解决

技能 3 · design-action-combat

独立可构建 游戏开发
⚔️
design-action-combat
为网页游戏设计、实现、调优可读的战棋类动作战斗系统。用于攻击计时、格挡/闪避窗口、命中反馈、姿态、锁定、武器、Boss 阶段、战斗反馈、确定性战斗测试。
✅ 通过
真实场景
用这个技能的"状态机 + 显式计时"原则，构建一个可运行的网页版"战棋式动作战斗"原型：玩家 vs 史莱姆，有攻击/格挡/闪避三种操作，有 startup/active/recovery 三帧窗口概念。
design-action-combat 核心原则 → 代码实现
/* 技能原则 1: 把战斗当作状态机 */
const CombatState = {
  IDLE:      'idle',
  STARTUP:   'startup',  // 前摇 — 不可取消，可被中断
  ACTIVE:     'active',    // 命中窗口
  RECOVERY:   'recovery', // 后摇 — 不可取消
  BLOCKING:   'blocking', // 格挡 — 持续到松键或被破
  DODGING:    'dodging',  // 闪避 — i-frames
  HIT:       'hit',      // 命中硬直
  DEAD:      'dead',
};

/* 技能原则 2: 防御有明确目的 */
// 格挡 — 完美时机减免伤害，失败则破防
// 闪避 — i-frames 无敌帧，穿敌
//  spacing — 拉开距离，规避范围攻击

/* 技能原则 3: 视觉反馈跟随模拟事件 */
function resolveHit(actor, target, damage) {
  if (target.state === CombatState.BLOCKING) {
    target.hp -= Math.floor(damage * 0.1); // 格挡成功，只受 10%
    spawnVFX('block-spark', target.pos);
  } else if (target.state === CombatState.DODGING) {
    // 闪避成功，无伤害，无视
  } else {
    target.hp -= damage;
    spawnVFX('hit-flash', target.pos);
    target.setState(CombatState.HIT, 300);
  }
}
design-action-combat 实战验证 — 状态机战斗原型
✅
状态机原则有效
7 个显式状态的枚举让战斗逻辑高度可预测和可测试
✅
防御三角明确
格挡（减伤90%）/ 闪避（i-frames）/ spacing（拉开）各有明确代价和收益
✅
确定性测试可行
纯状态机 + 固定 timer，无需随机种子就能验证连击、格挡、闪避边界
💡
SKILL 没给代码
这是设计原则型 SKILL，不是工具型。给出了概念框架，具体代码需自己实现
⚠️
输出难度高
需要游戏开发经验才能把"姿态/前摇/命中窗口"翻译成正确的状态转换代码
💡
适合培养
对 AI Agent 来说，这个 SKILL 是"设计约束"而非"代码模板"，需要更多推理

技能 4 · video-to-superprompt

需平台配合 AI 工作流
🎬
video-to-superprompt
将参考视频转换为超级详细的重建 Prompt。用于用户提供/上传/链接视频，要求分析设计、UI、动画、过渡、视差交互、字体、颜色、素材、WebGL/Three.js、叙事、分段行为时触发。
⚠️ 需平台
真实场景
用户提供了一个 Awwwards 获奖落地页的滚动录屏（MP4），需要 AI 生成一个可以直接重建该页面效果的"超级 Prompt"。
video-to-superprompt 工作流分析
/* 技能定义的 6 步工作流 */

Step 1  定位 — 接受本地路径/上传/URL/浏览器可见视频
Step 2  技术检查 — ffprobe 尺寸/帧率/码率，ffmpeg 提取关键帧
Step 3  分层分析 — Story / Screen-layout / Motion / Visual / Technical rebuild
Step 4  素材规划 — 产出 asset map，区分 AI 生成素材 vs 指定素材
Step 5  写超级 Prompt — 单个 fenced text 块，边界 + 全局语言 + 分段解剖 + 运动系统
Step 6  验证 — 确认所有素材路径存在/标记为 placeholder

/* 质量 Bar — 评估标准 */
• Prompt 长度足够不看原视频重建动画
• 保留视频的序列、节奏、特殊细节
• 命名精确的运动机制：pinned section / scrubbed timeline / video.currentTime / parallax layer
• 包含移动端行为和 reduced-motion 降级方案
• 指出要避免的：通用落地页 sections / 装饰性 blobs / 不匹配 stock 媒体
测试结论
工作流设计非常成熟：分层分析（6 个维度）+ 质量 Bar（5 条）+ 输出模式（4 种）都很完整。
但无法独立测试：Step 2 需要 ffprobe/ffmpeg，Step 5/6 需要 AI 模型执行。
这个 SKILL 本质上是AI Agent 的标准操作程序（SOP），它的价值在于提供了统一的分析框架和质量标准，而不是生成具体代码。
✅
工作流完整
6 步链路清晰，从原始视频到可用 Prompt 覆盖完整
✅
质量 Bar 可测试
5 条质量标准具体可操作，可用来验证 Prompt 是否达标
⚠️
依赖平台工具
ffprobe/ffmpeg 是 CLI 工具，在纯浏览器环境无法执行
💡
对 AI Agent 的价值
提供标准分析框架，让不同 AI 对同一视频输出一致的分段解剖

Layer 3 · 测试总结

技能 类别 可构建 质量 结论
beautiful-shadows CSS 特效 直接可用 优秀 box-shadow 值直接复制，质感远超默认 Tailwind
animation-on-scroll 视口动画 直接可用 良好 零依赖，但 stagger 方案需自己补充
design-action-combat 游戏开发 设计原则 优秀 原则清晰可落地，但需要游戏开发经验配合

💡 对我们自己的 Agent Skills 库的启发

  • 工具型技能（beautiful-shadows, animation-on-scroll）：直接给可复制的代码片段，质量极高，AI 使用时几乎零摩擦
  • 原则型技能（design-action-combat）：给出设计约束和评估标准，落地需要更多专业判断，适合高阶 Agent
  • 工作流型技能（video-to-superprompt）：提供 SOP，质量 Bar 可测试，但依赖平台工具，适合云端 AI Agent
  • 最值得学习的：Beautiful Shadows 的"避免指南"（pitfalls）非常实用，我们自己的技能也应该加
  • 可以补充的：animation-on-scroll 缺少 stagger 方案的明确说明，实际用时需要自己探索
