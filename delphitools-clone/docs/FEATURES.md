# 56 工具功能覆盖矩阵

本表以当前注册表、引擎和工作区为准，描述用户实际可操作的范围，不把设计愿景或浏览器模拟测试扩大成产品能力。共 56 个精确 ID；标准格式名保留英文，并在中文语境中解释。

通用边界：文件处理在浏览器本地完成；图片与 PDF 能否读取/导出仍受浏览器 API、内存和格式支持影响。基础图片 Canvas 输出单边上限 16384 像素、总像素上限 8000 万；背景移除与图片追踪的栅格输入上限 2000 万像素。

## 能力与实现说明（批次 1）

每一个工具页都会在工作区内容之后显示中文“能力与实现说明”面板。面板逐工具说明实际可用的能力、输入、输出、算法/实现原理、使用流程、隐私边界和已知限制；状态为“当前无法完整实现”的条目还会明确列出未实现原因。说明基于当前实现，而不是产品设想或测试替身。

`/capabilities` 是全量状态总览页：它显示 56 个工具卡片，提供状态筛选，并复用与各工具页完全相同的逐工具说明数据。状态统计如下：

| 状态 | 数量 | 含义 |
| --- | ---: | --- |
| 完整实现 | 0 | 核心能力、主要格式和主要流程均已对齐。 |
| 主要能力完整 | 17 | 核心任务可靠，仅缺次要快捷操作或展示细节。 |
| 部分实现 | 24 | 主要任务可完成，但仍缺重要格式、模式、交互或数据范围。 |
| 当前无法完整实现 | 15 | 核心算法、数据或主要模式尚未达到可靠实现标准。 |

这些 0/17/24/15 数量覆盖全部 56 个精确工具 ID；“部分实现”与“当前无法完整实现”合计 39 项，适合作为后续补齐工作的队列，而非隐含承诺。批次 1 已补齐颜色、纸张、密码、Meta/正则、文本、进制与科学计算的低风险本地能力；下一批仍聚焦批量操作、真实文件导出和图像工作流，不宣称 56 项均完整。
