# DelphiTools 维护交接

## 架构概览

项目是一个 Vite + React + TypeScript 单页应用。`src/data/tools.ts` 是 56 个入口的注册表，`src/core/types.ts` 锁定工具 ID 与分类；应用壳负责首页、中文搜索、分类导航、主题和路由，具体工具由工作区组件承载。

当前能力按 7 个工作区组织：

| 工作区 | 入口数 | 职责 |
| --- | ---: | --- |
| `ImageWorkspace` | 13 | Canvas 图片处理、社交裁剪、Base64、剪贴板图片 |
| `ColorWorkspace` | 10 | 颜色转换、对比度、配色、图片取色 |
| `TextWorkspace` | 11 | 文档、Markdown、字体、Unicode、排版与文本统计 |
| `DeveloperWorkspace` | 10 | 条码、二维码、正则、编码、Meta、密码和 Shavian 转写 |
| `CalculatorWorkspace` | 5 | 代数、科学计算、绘图、时间和单位换算 |
| `PdfWorkspace` | 6 | 背景移除、图片追踪、SVG 净化、PDF 预检与拼版 |
| `EditorWorkspace` | 1 | Substrata Canvas 图层编辑器 |

这里的总数按入口映射计算为 56；背景移除和图片追踪虽属于图片能力，为复用 Worker 生命周期和高级任务状态而由 `PdfWorkspace` 承载。

## 目录职责

```text
src/
├─ app/          应用入口、首页、路由、未找到页
├─ components/   应用壳、上传/结果/状态组件、编辑器面板
├─ core/         类型、文件读取、剪贴板、下载、主题
├─ data/         工具注册表、分类、纸张/Unicode/调色板等静态数据
├─ engines/      可测试的纯处理逻辑与浏览器导出逻辑
├─ tools/        七个工作区与各入口的中文控件
├─ workers/      高级图片与 PDF 后台线程
└─ styles/       主题、布局、组件和编辑器样式
tests/           引擎、工作区、路由和资源清理回归测试
docs/            功能矩阵、验收和本交接文档
```

## 动态工作区状态

`ToolPage.tsx` 已通过 `React.lazy` 与动态 `import()` 按工作区加载。首页不会装入 `pdf-lib`、条码/二维码引擎或 Substrata 编辑器；未知路由和分块加载失败均有中文恢复界面。最终拆包尺寸、测试和浏览器证据记录在 `VALIDATION.md`。

## Worker 与异步资源

- `backgroundRemoval.worker.ts`：执行本地颜色距离与边缘连通背景分割。
- `imageTrace.worker.ts`：执行本地像素扫描式 SVG 追踪。
- `pdf.worker.ts`：执行 PDF 预检、N-up/小册子拼版和 8 页 Zine 生成。
- `protocol.ts`：定义进度、成功、错误和取消消息。

工作区使用任务版本号丢弃迟到结果，并在新输入、参数变化、取消或卸载时终止 Worker。注意：Worker 内同步循环无法在不让出事件循环时处理取消消息，当前有效取消手段是主线程 `terminate()`。若以后改为可续跑任务，应把大循环分片并定期让出执行权。

对象 URL、FileReader、Image 事件和 AbortController 也属于生命周期的一部分。任何新工具都应覆盖“替换结果、失败、重置、卸载”四种清理路径；不得把上一任务的成功结果留在新错误下。

## 增加新工具

1. 在 `src/core/types.ts` 的 `ToolId` 中加入稳定 ID；不要复用或静默改名现有 ID。
2. 在 `src/data/tools.ts` 注册中文标题、中文说明、中文关键词、分类、工作区和模式。标准格式名可保留英文，但必须有中文上下文。
3. 优先把确定性逻辑放进对应 `src/engines/*.ts`，工作区只处理输入、状态、预览和导出。
4. 将入口接到现有工作区；只有交互模型或重依赖边界真正不同才新增工作区。同步更新动态 loader 映射。
5. 为引擎写边界测试，为真实路由写中文控件、有效/无效输入、成功/重置/失败测试；耗时任务再覆盖竞态、取消和卸载清理。
6. 如果生成文件，测试 MIME、扩展名和文件签名/结构，不能只改扩展名伪造格式。
7. 更新 `FEATURES.md` 的输入、输出、实现范围和真实限制，并在 `VALIDATION.md` 增加验收旅程。
8. 运行精确 ID 测试、全量测试、生产构建、依赖审计、静态禁用 API 检查和真实浏览器复验。

## 维护重点

- 保持 `src/data/tools.ts`、`ToolId`、工作区 loader 和 `FEATURES.md` 四处 ID 集合一致；以精确集合测试防止遗漏、重复和意外改名。
- 不使用 `eval` 或 `new Function` 计算表达式；数学工具继续走白名单解析器。
- 不新增远程上传路径。若未来确需外部服务，必须先取得新的产品与隐私授权，并在界面中清楚说明。
- 新依赖先评估体积、浏览器支持、安全告警和许可证。不要用 `npm audit fix --force` 盲目消除告警。
- 浏览器格式能力必须运行时探测。Canvas 当前只可承诺实际编码成功的 PNG/JPEG/WebP，不能把 MIME 或扩展名改写当作转换。
- 保持中文错误可恢复：说明发生了什么、旧结果是否已清除、用户下一步能做什么。

## 已知限制摘要

- 背景移除是非 AI 的四角估色、颜色距离和边缘连通分割；复杂背景、毛发与半透明主体效果有限。
- 图片输出受 Canvas、浏览器解码器和内存限制；基础图片输出单边不超过 16384 像素且总像素不超过 8000 万，高级栅格算法上限 2000 万像素。
- 图片转换不输出 GIF/BMP/TIFF/ICO；Favicon 输出多张 PNG，不生成 `.ico` 或 ZIP；网格切图与多尺寸结果逐个下载。
- 文档转换是常用 Markdown/HTML 子集；DOCX 仅基础文字 OOXML，EPUB 为单章节，LaTeX 依赖外部 `ctex` 环境编译。
- 字体浏览只支持单字体 TTF/OTF SFNT；`name` 字符串记录已限制在对应表内部，但仍不是完整字体校验器。
- PDF 预检不分析字体嵌入、出血、ICC、油墨或完整印刷合规；拼版嵌入页不会保留注释、链接和交互表单组件，也不支持加密 PDF。
- 正则在可终止 Worker 中运行，500ms 超时、最多收集 10000 个匹配；复杂但有效的表达式可能因预算而被拒绝。
- 代数不是通用计算机代数系统；绘图有采样和深探测预算；温度换算会拒绝低于绝对零的输入。
- Substrata 当前只导出 PNG，历史上限 50；多行文字预览使用文本框，但 Canvas 导出仍是单次 `fillText`，换行布局不完全一致。
- 真实浏览器文件选择控制层曾出现 466 秒和 776 秒超时。它们是自动化控制层事件，不是产品失败或通过证据；重测条件见 `VALIDATION.md`。
## 工具说明系统与批次 1 交接

`src/data/toolExplanations.ts` 是逐工具说明和未完整实现清单的唯一事实源。它定义全部 56 个精确工具 ID 的状态、能力、输入、输出、实现原理、流程、隐私说明、限制，以及“当前无法完整实现”项目的缺失原因。`ToolExplanationPanel` 在各工具页使用这份数据，`/capabilities` 使用同一数据渲染 56 张卡片和状态筛选；不要把页面显示的事实复制成独立、会漂移的文案来源。

当前状态基线为：完整实现 0、主要能力完整 17、部分实现 24、当前无法完整实现 15（合计 56）。`getIncompleteToolExplanations()` 返回后两类，共 39 项，供后续优先级排序使用。

后续补功能时，必须在同一个变更中同步更新对应 `src/data/toolExplanations.ts` 条目的：

1. 状态；
2. 实际能力、输入和输出；
3. 算法/实现原理与使用流程；
4. 隐私说明、限制和（如适用）未实现原因；
5. 对应测试与 `docs/FEATURES.md` 的覆盖矩阵。

不得只更新审计 Markdown 而遗漏页面数据，也不得只改页面数据而保留过期的能力矩阵。状态数量、`/capabilities` 卡片和工具页说明必须与事实源保持一致。

批次 1 已完成颜色坐标与和谐/色阶、86 个纸张规格、密码解码、Meta/正则、文本处理、进制/位运算和科学计算器的低风险本地能力。下一批仍应优先处理批量操作、真实文件导出和图像工作流；机器学习抠图、专业 PDF 和 Substrata 的大规模扩展仍需独立计划，不能据此声称 56 项工具都已完整实现。
