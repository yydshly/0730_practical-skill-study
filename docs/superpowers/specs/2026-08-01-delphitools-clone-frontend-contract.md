# Delphitools 中文工具箱前端交付契约

## 设计契约

- **进入方式：** 参考网页驱动，并基于已确认的中文功能规格实施。
- **请求版本：** 1。
- **目标用户与场景：** 需要快速处理图片、颜色、文字、PDF、开发编码和计算任务的中文创作者、设计师与开发者。
- **第一印象：** 一眼看懂这是一个无需登录、分类清晰、可以立即使用的中文浏览器工具箱。
- **视觉目标：** Functional，功能清楚优先，同时保留参考网页手工工具站的克制气质。
- **体验架构：** Editorial Flow；首页按精选与分类浏览，工具页按“输入 → 参数 → 预览/结果 → 导出”展开。
- **视觉约束：** 左侧分类导航、顶部搜索、工具卡片、浅色/深色主题、清晰焦点态；不复制参考站品牌素材。
- **信息约束：** 所有主要用户文案使用简体中文；PNG、SVG、Base64、WCAG 等标准术语保留原写法并提供中文上下文。
- **操作约束：** 无账号、无项目自有后端、文件尽量在浏览器本地处理；所有处理都提供明确的重置、复制或下载出口。
- **状态约束：** 每个工具至少覆盖空状态、有效输入、无效输入、成功结果；耗时工具额外覆盖加载、处理中、失败和恢复。
- **环境约束：** 桌面端目标宽度 1440px，平板目标宽度 900px，手机目标宽度 390px；支持浅色和深色主题、键盘导航与 reduced-motion。
- **主要旅程：** 搜索或浏览工具 → 进入工具 → 输入文件/文本/参数 → 处理 → 查看结果 → 复制或下载。
- **用户阶段：** 平台基础、图片工具、颜色工具、文字与开发工具、数学与排版工具、高级媒体工具、Substrata 编辑器、全量验收。
- **必需产物：** 设计规格、实施计划、可运行源代码、中文 README、测试、构建产物、浏览器验收记录和交付说明。
- **自主授权：** 用户已明确回复“确认”和“继续实现”，允许在已确认范围内直接完成可逆的设计、编码、测试和文档工作。
- **用户决策边界：** 只有新增后端、登录、真实外部服务、付费能力、品牌资产复制或不可逆外部操作需要新的用户决定。
- **可观察完成标准：** 所有工具入口可访问且产生实际结果；主要旅程可完成；关键状态、主题、宽度和键盘路径有浏览器证据；测试和构建通过。

## 参考差异与视觉方向

| 层级 | 参考特征 | 本项目方向 | 验收标准 |
| --- | --- | --- | --- |
| 构图 | 左侧分类导航，右侧工具内容 | 桌面固定侧栏，移动端抽屉导航 | 主要操作在三种目标宽度下可到达且无裁切 |
| 焦点 | 工具名称和操作区域最突出 | 中文工具名、用途说明和主操作形成清晰层级 | 首屏能识别当前工具与下一步动作 |
| 字体 | 工具站式中性排版 | 中文系统字体为主，等宽字体用于代码和数值 | 长中文标签不截断，数值结果易读 |
| 色彩 | 克制的浅色/深色工具界面 | 语义色令牌覆盖成功、警告、错误、焦点 | 两种主题下文字、控件和状态可辨认 |
| 材质 | 细边框、卡片和轻量面板 | 使用边框和轻阴影表达分组，不做重装饰 | 输入、预览、结果区域边界明确 |
| 密度 | 工具多但分类明确 | 首页紧凑，工具页留出足够操作空间 | 搜索与分类可快速定位，表单不拥挤 |
| 动效 | 轻量状态变化 | 仅用于抽屉、反馈和进度；尊重 reduced-motion | 关闭动效后信息和操作不受影响 |
