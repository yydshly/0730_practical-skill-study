# GC Minimal Zine Poster · 场景产品展厅设计规格

日期：2026-08-01  
状态：待用户审阅

## 1. 目标

在现有 `gc-minimal-zine-poster/demo/` Prompt Compiler 研究实验台下方新增一个桌面优先的“场景产品展厅”，让使用者不只看到它如何编译 Prompt，也能看到它在真实产品场景中能产出什么视觉结果。

展厅需要同时完成两件事：

1. 用清晰的场景描述解释谁会使用这个 Skill、要制作什么产品、输入什么内容以及为什么适合。
2. 为每个场景提供一张独立的、由内部 Codex 图像能力提前生成的真实本地 JPEG 样张，不使用占位图，也不在浏览器运行时调用 API。

## 2. 现有边界与本次调整

- 保留现有三栏 Prompt Compiler、Recipe、Quality Gate 和四张基础样张，不改变其行为。
- 展厅是现有页面下方的新增模块，不替换核心实验台。
- 本轮只验证桌面端 1440px 和 1024px；暂不把移动端布局作为验收条件。
- 新增 10 个场景，每个场景对应 1 张独立真实生成图，共 10 张本地 JPEG。
- 每张生成图旁边必须显示 `GENERATED SCENARIO SAMPLE`，明确它是提前生成的研究样本。
- 每张图片的 Prompt、场景 ID、产品类型、生成日期和文件路径写入本地 manifest。
- 不新增后端、API key、远程字体、运行时图像服务或浏览器端 Codex 调用。

“真实生成效果”在本轮的定义是：图片确实由内部 Codex 图像能力生成，并以本地 JPEG 形式进入 Demo；不是 CSS 占位图或仅有文字的 mockup。浏览器即时输入后生成新图片属于后续独立阶段，不纳入本轮。

每个场景都要在卡片和详情面板中展示以下信息：使用者、产品、输入示例、视觉目标、适配原因和建议交付物。

| ID | 场景 | 使用者 | 产品 | 输入示例 | 视觉目标 | 建议交付物 |

## 4. 信息架构

页面结构保持单页研究流：

```text
现有 Prompt Compiler 实验台
  ├─ Input
  ├─ Generated Sample
  └─ Prompt / Recipe / Quality Gate
新增 Scenario Product Gallery
  ├─ 场景说明头部
  ├─ 10 张场景卡片网格
  └─ 当前场景详情 + 真实生成样张
现有 Upstream References
```

场景展厅采用两段式桌面布局：左侧为 10 张卡片网格，右侧为固定的当前场景详情面板。1024px 时变为上下两段；移动端本轮不作为验收范围，但 CSS 不应主动引入新的横向滚动。

## 5. 数据与接口

在 `demo/js/data.js` 增加 `SCENARIO_SHOWCASES`，每行至少包含：

```js
{
  id,
  category,
  audience,
  product,
  brief,
  visualGoal,
  whyItFits,
  deliverables,
  assetId,
  accentColor,
}
```

在 `demo/assets/generated/manifest.json` 增加 10 行场景资产记录，字段保持与现有资产一致，并额外保存 `scenarioId`。每个 `assetId` 只对应一个新 JPEG，文件放在 `demo/assets/generated/scenarios/`。

`app.js` 只负责把数据映射到 DOM，不在组件中硬编码场景文案。新增稳定 DOM hooks：

- `scenario-gallery`
- `scenario-grid`
- `scenario-detail`
- `scenario-active-category`
- `scenario-active-title`
- `scenario-active-description`
- `scenario-active-product`
- `scenario-active-brief`
- `scenario-active-why`
- `scenario-active-deliverables`
- `scenario-active-image`
- `scenario-active-caption`

## 6. 交互与可访问性

- 首次加载默认选中 `indie-zine-cover`。
- 每张场景卡为原生 `button` 或可键盘操作的按钮结构。
- 当前卡片有明确的 active 状态、`aria-pressed` 和可见焦点。
- 点击或按 Enter / Space 后，详情标题、文案、产品标签、输入示例、交付物和图片同步更新。
- 场景图片使用真实本地 JPEG，详情 caption 显示场景 ID、生成日期和“预生成本地样张”。
- 详情面板不是运行时生成器，不显示“正在生成”或虚假的 API 状态。
- 既有 Prompt Compiler 的复制、空输入、Variation、Dialog 和键盘流程必须保持不变。

## 7. 视觉方向

场景展厅延续现有 warm paper / graphite shell 视觉系统，但增加明确的产品化表达：

- 场景卡片使用纸张白底、细边框和小型分类标签。
- 当前详情面板使用略深的纸张层级，让真实样张成为视觉焦点。
- 每个场景卡显示一个小型“Product”标签，避免用户只看到抽象风格而看不懂使用场景。
- 图片统一使用竖版 3:5 样张框；音乐 EP 场景也保留纸张海报比例，说明这是该 Skill 的视觉输出，不是最终平台裁切稿。
- 不使用远程图片、远程字体或需要运行时网络的装饰。

## 8. 真实图像生成流程

为 10 个场景分别使用内部 Codex 图像能力生成一张独立海报。每个 Prompt 必须同时包含：

- 场景输入和产品语境
- Standard Mode 的 3:5 竖版纸张、70%–90% 留白和一个清晰视觉锚点
- 一个主要高饱和色和印刷 / 扫描 / 纸张质感
- 场景对应的产品氛围
- 共同 hard avoids：商业广告布局、光亮样机、3D、霓虹、电影感布光、密集拼贴、长段干净文字

生成后逐张检查：

1. 图片是否真实存在且非空。
2. 是否能在缩略图中识别场景主体。
3. 是否保留明显的留白和单一色彩锚点。
4. 是否能让使用者理解它对应的产品场景。
5. manifest 中的 Prompt、文件名、场景 ID 与页面展示一致。

## 9. 测试与证据

采用 TDD 先增加浏览器行为断言，再写场景渲染代码：

- 初始场景卡片数量为 10。
- 默认详情标题为 `indie-zine-cover` 对应标题。
- 点击另一张卡后，详情标题、产品文案和图片 src 同步变化。
- 使用键盘聚焦卡片并按 Enter 后，详情更新。
- 当前场景图片 src 指向 `assets/generated/scenarios/*.jpeg`，不是占位路径。
- 1440px 和 1024px 下场景网格、详情面板和图片可见且无横向溢出。
- 既有 compiler test 和 browser smoke 全部继续通过。

最终证据保留：

- 1440px 场景展厅默认状态截图。
- 1440px 选择第 7 个场景后的详情截图。
- 1024px 场景展厅截图。
- 10 张生成 JPEG 与 manifest 文件检查记录。

## 10. 明确不做

- 不在浏览器运行时调用 Codex 或外部图像 API。
- 不实现账户、项目保存、收藏、导出或数据库。
- 不把 10 个场景拆成 10 个独立页面。
- 不在本轮优化移动端体验；仅保持没有明显破坏性的基础布局。
- 不把这些预生成样张标记为用户输入后的即时生成结果。
