# Delphitools 中文工具箱设计规格

**日期：** 2026-08-01  
**项目目录：** `F:/0730_vscode_claude_project/delphitools-clone`  
**参考网页：** `https://tools.rmv.fyi/`

## 1. 目标

建立一个独立的中文化浏览器工具箱，覆盖参考网页中可见的图片、颜色、文字、印刷、开发、数学和特殊文字能力。项目不要求逐像素复制参考网页，而是保留其“分类工具箱 + 单工具页面 + 本地处理 + 可下载结果”的核心体验。

所有用户可见的标题、按钮、字段、帮助文本、错误提示和空状态默认使用简体中文；文件格式、编码格式、CSS 属性和数学符号等行业术语保留标准写法，并在必要处给出中文解释。

## 2. 范围与非目标

### 2.1 本次范围

- 创建一个独立前端项目，不修改现有工作区中的其他项目。
- 提供首页、分类导航、中文搜索、工具详情页和主题切换。
- 为参考网页中的全部工具入口提供可实际操作的实现。
- 优先使用浏览器本地 API、Web Worker 和前端库处理数据。
- 图片、文本、颜色、计算和 PDF 结果都应提供复制、下载或导出路径。
- 为核心纯函数和关键用户流程提供自动化测试与浏览器验收。

### 2.2 非目标

- 不实现账户体系、云端项目、团队协作、付费和后台数据库。
- 不上传用户图片、文档或文本到项目自有服务器。
- 不把所有工具写进一个页面或一个巨型组件。
- 不承诺与参考网页的私有实现、内部代码或品牌资产完全相同。

### 3.2 Substrata 图片编辑器

`editor` 是独立的画布工具，不与简单图片处理表单混在一起。

- 导入多张图片并创建画布。
- 拖拽、缩放、旋转和调整图层顺序。
- 添加文字、矩形、圆形、箭头和标记。
- 调整透明度、填充色、描边和基本对齐方式。
- 支持从剪贴板粘贴图片。
- 可撤销、重做、清空和重新开始。
- 导出 PNG、JPEG 和 WebP。

## 4. 技术架构

### 4.1 项目技术

- 使用 Vite、React 和 TypeScript 构建。
- 使用浏览器路由实现首页与工具页切换。
- 使用 CSS 变量实现中英文案、主题颜色和响应式布局。
- 使用 Web Worker 执行背景移除、图片追踪、PDF 和批量图片处理。
- 通过统一工具注册表实现按分类加载和懒加载。

### 4.2 目录边界

```text
delphitools-clone/
├─ src/
│  ├─ app/                  应用壳、路由和页面
│  ├─ components/           上传区、预览区、按钮、参数面板等通用组件
│  ├─ core/                 文件、剪贴板、下载、主题和错误处理
│  ├─ data/                 分类、中文名称、描述和帮助文案
│  ├─ tools/
│  │  ├─ image/             图片与社交媒体工具
│  │  ├─ color/             颜色工具
│  │  ├─ text/              文字、排版和字体工具
│  │  ├─ print/             PDF 和印刷工具
│  │  ├─ developer/         开发和编码工具
│  │  ├─ calculator/        数学和计算工具
│  │  └─ editor/            Substrata 编辑器
│  ├─ workers/               耗时任务 Worker
│  └─ styles/                全局样式和主题
├─ public/                   模型、字体和静态文件
├─ tests/                    单元、组件和浏览器烟雾测试
└─ docs/                     使用说明和实现记录
```

### 4.3 工具接口

每个工具通过统一定义注册：

```ts
type ToolDefinition = {
  id: string;
  category: ToolCategory;
  title: string;
  description: string;
  keywords: string[];
  component: LazyExoticComponent<ComponentType>;
};
```

工具组件只负责自己的输入、处理和结果展示；上传、下载、错误提示、主题和导航由公共层负责。

### 4.4 本地数据流

```text
文件/文本/颜色输入
        ↓
公共输入适配层
        ↓
工具自己的纯处理函数或 Web Worker
        ↓
预览/结果对象
        ↓
复制、下载或导出
```

用户输入不发送到项目自有服务器。背景移除等需要模型的功能会使用本地模型文件；若首次加载模型需要下载，界面必须明确显示模型来源、大小和加载状态。

## 5. 中文化规则

- 页面标题使用中文，例如“图片格式转换”，不直接显示 `Image Converter`。
- 英文工具名可作为辅助小字显示，方便查找资料。
- 常见技术格式保留原写法，例如 PNG、JPEG、Base64、SVG、WCAG。
- 所有按钮使用动作型中文，例如“选择图片”“开始转换”“复制结果”“下载文件”。
- 所有空状态和错误信息必须告诉用户下一步怎么做。
- 不使用只有英文的占位符、提示语或错误堆栈作为主要用户反馈。

## 6. 复杂能力的处理策略

### 6.1 背景移除

采用浏览器端模型，不上传用户图片。模型处理放入 Worker；界面需要展示“加载模型”“处理中”“处理完成”和失败状态。

### 6.2 图片转 SVG

针对图标、线稿和高对比度图片提供可控追踪；需要说明照片类图片不适合直接转成高质量矢量图。

### 6.3 PDF

使用浏览器端 PDF 解析与生成能力，输入、页面预览、页面顺序和导出均在本地完成。

### 6.4 文档转换

优先保证 Markdown 与 HTML 的双向转换，并提供 Word、LaTeX、EPUB 的可用导入或导出路径；不承诺复杂排版文档的完全还原。

## 7. 测试与验收

### 7.1 单元测试

覆盖颜色转换、调色板生成、对比度、图片尺寸计算、文本统计、文本差异、进制转换、时间换算、单位换算和 PDF 页面排序等纯逻辑。

### 7.2 组件测试

覆盖文件选择、拖拽输入、错误提示、重置、复制和下载按钮的状态变化。

### 7.3 浏览器验收

至少验证以下完整路径：

1. 首页搜索“图片格式转换”，进入工具并完成一次格式转换。
2. 上传图片，提取调色板并复制颜色值。
3. 输入文本，完成差异比较并复制结果。
4. 生成二维码并下载图片。
5. 进行单位换算和函数绘图。
6. 使用 Substrata 导入两张图片并导出画布。
7. 切换深色主题，并在移动宽度下确认导航和工具表单可用。

### 7.4 完成标准

- 参考网页的每个工具都有中文入口和实际功能。
- 图片、文本、颜色、计算和 PDF 工具都能产生可验证结果。
- 关键导入、处理、错误和下载状态都有中文反馈。
- 不需要登录或自建后端。
- 构建、自动化测试和浏览器验收均通过。
- 复杂工具如果存在格式限制，必须在页面中明确说明，而不是静默失败。

## 8. 实施拆分

实施时保持一个项目、一个最终版本，但按以下边界开发和测试：

1. 平台基础：应用壳、导航、搜索、主题、工具注册和公共输入输出组件。
2. 图片基础工具：转换、裁剪、缩放、分割、拼接、水印、衬底、Favicon、Base64、透明边缘裁剪。
3. 颜色工具：颜色转换、调色板、渐变、和谐、对比度、色盲模拟、取色器和 Tailwind 色阶。
4. 文字与开发工具：编辑器、差异比较、统计、编码、正则、二维码、条形码、Meta 和密码工具。
5. 数学与排版工具：科学计算、代数、绘图、单位、时间、字体、纸张、行高和排版工具。
6. 高级媒体工具：背景移除、图片转 SVG、PDF 预检、PDF 拼版、Zine 拼版和文档转换。
7. Substrata 编辑器：画布、图层、标注、撤销重做和导出。
8. 全量中文化、交互修整、构建、测试和浏览器验收。

这些是代码组织边界，不代表向用户交付多个半成品；最终交付应是一个统一的完整工具箱。
