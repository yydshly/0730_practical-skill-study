# 女性人像风格展廊：根目录交付与卡片提示词修订

## 修订背景

新版 `female-portrait-style-gallery` 已在隔离工作树中实现，但尚未合并到项目根目录。用户从根目录打开网页时仍会进入旧项目，因此无法看到新版的二十种风格。现有规格还要求双击 `index.html` 可运行，而当前 ES module 入口在 `file://` 环境中可能被浏览器安全策略阻止，两者需要一并修正。

## 已确认方案

采用卡片提示词摘要方案：每张图片下方直接展示三至四行提示词摘要，并提供独立的“复制提示词”按钮；详情弹窗继续展示完整提示词与摄影拆解。这样既满足提示词可见性，又避免二十张卡片因完整长提示词而过度拉长。

## 页面入口

- 完成验证后，将开发分支合并回 `female-portrait-director-demo` 基线分支，使新项目实际位于 `F:\0730_vscode_claude_project\female-portrait-style-gallery`。
- 页面必须支持通过本地 HTTP 服务打开。
- 页面也必须支持直接双击 `index.html`，不得依赖 `file://` 环境禁止的模块加载方式。
- 两种入口都必须渲染二十张风格卡片；缺少正式图片时显示带编号占位，不隐藏卡片、名称或提示词。

## 卡片交互

- 图片、编号、分类、名称与风格描述保持现有层级。
- 描述下方新增提示词区域，默认显示三至四行，使用与正文可区分但仍可读的次级表面。
- 每张卡片提供“复制提示词”按钮。点击按钮只复制，不打开详情，并显示成功或失败反馈。
- 点击卡片其他区域仍打开详情弹窗；键盘操作路径保持一致。
- 详情弹窗继续显示完整提示词、场景、造型、镜头和光线，并保留复制按钮。

## 数据与实现边界

- `js/styles.js` 仍是二十种风格与提示词的唯一内容源，避免卡片与详情内容不一致。
- 为支持双击打开，可以把浏览器运行入口打包为普通脚本，但源数据和纯筛选工具继续保留为可测试模块。
- 不引入后端、API Key、远程字体或运行时网络依赖。
- 图片继续使用 Codex 对话内置生图能力逐张生成，不切换到本地 API，除非用户以后明确要求。

## 验收标准

- 项目根目录存在 `female-portrait-style-gallery`，不再只存在于 `.worktrees`。
- HTTP 与直接打开两种方式均可看到二十张卡片和九类筛选。
- 每张卡片图片下方可见提示词摘要与复制按钮。
- 卡片复制不会误开详情；复制、详情、Esc、焦点返回、搜索、筛选和空状态均通过自动化验收。
- 1440、768、390 三种视口无页面级横向溢出。
- 图片数量如实记录；未生成图片使用明确占位，不将占位计作正式样例。

## 非目标

- 不修改原有 `female-portrait-director-demo` 的功能和界面。
- 不把完整提示词永久展开在所有卡片中。
- 不增加在线生图、账号、历史记录或上传功能。
